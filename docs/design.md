## 0. 一句话

用 OKX 上的 USDT 挂 maker 单买 ETH,同时在 OKX 开等量的 ETH 永续空单锁住价格;你把 ETH 手动提到 OSL,在 OSL 手动卖成 USD,每卖一笔就在程序里输入成交量,**程序立刻在 OKX 平掉对应数量的空单**;最后对账,算出实际兑换率和每一项成本。

| | 程序做 | 你手动做 |
|---|---|---|
| 资金 | OKX 资金账户 → 交易账户划转 | OKX 提币 → hot wallet → OSL;OSL 资金账户↔交易账户划转;OSL 出金 |
| 交易 | OKX 现货 maker 买 + 同步开空;按你输入的成交量同步平空 | 在 OSL 卖出 ETH |
| 查询 | OKX 余额、仓位;OSL 公开行情和兑换率;PnL 对账 | 在 OSL App 看余额、成交 |
| 通知 | 全部在命令行输出 | — |

## 1. 路线选择:OSL 手动 vs HashKey API

| | OSL(零售,手动) | HashKey(零售,API) |
|---|---|---|
| API | **零售不能用**(只给 PI / 企业 / 机构 / omnibus) | **可以用**,但要先在 API 管理页申请,填问卷和用途说明,审批后才能建 key,必须绑 IP |
| 零售能交易的 ETH 对 | ETHUSD | ETHHKD、ETHUSD(USDT、USDC 相关的交易对只给 PI) |
| 手续费 | maker 0% / **taker 0.05%** | VIP0 **maker = taker = 0.29%**(30 天交易量 ≥5 万美元降到 0.25%,≥100 万降到 0.15%);另外每笔全部成交的订单最低收 1.99 美元(8 月新费率下是否还有【待核实】) |
| 盘口(2026-10-14 实测) | 价差约 0.03 美元(约 0.1 bps) | 价差通常 1 个价格步长;相对 OKX 换算后没有明显溢价(±5 bps 以内) |
| 充值 | 只收白名单钱包、以太坊主网;不能从交易所直接充 | 同样要白名单钱包、以太坊主网;不能从 OKX / 币安直接充 |
| 出金 | USD 最低 50,OSL 不收费,1–2 个工作日;FPS 只支持港币 | HKD 走 FPS 几秒到账,每笔 5 港币;USD 每笔 10 美元 |
| 测试环境 | 有 sandbox,要申请 | 有 sandbox,要发邮件申请 |

**结论:用 OSL 手动卖。**
- HashKey 虽然能全自动,但手续费是 OSL 吃单的近 6 倍:卖 1 万美元,HashKey 0.29% 要 29 美元,OSL taker 0.05% 只要 5 美元。手续费在 HashKey 上 maker 和 taker 一样,挂 maker 也省不了钱。
- 小额测试时 HashKey 更不划算:一笔 72 美元的单如果被收 1.99 美元最低费,就是 2.7%。
- 你担心的 ETH/HKD 溢价实测不存在;单位也不是问题,HashKey 零售同样有 ETHUSD。HashKey 真正的「溢价」就是手续费。
- HashKey 唯一的优势是港币 FPS 出金又快又便宜。以后如果你需要港币到账,或者量大到费率档位明显下降,可以再评估。

## 2. 整体流程

```
阶段            在哪里             谁做           ETH 价格风险
──────────────────────────────────────────────────────────────────────
P0 预检/建轮    OKX                程序           无
P1 买入+开空    OKX 现货+永续      程序(全自动)  已对冲(误差 < 0.0005 ETH)
P2 转账         OKX→钱包→OSL       你             已对冲(空单一直保留)
P3 卖出+平空    OSL 手动 + OKX     你卖,程序平   只在「你卖出」到「你按回车」之间的几秒钟
P4 收尾+对账    OKX                程序           无
```

资金流(以 300U、两轮为例,1x):

```
OKX 资金账户 300U
  └─(P0 划转)→ OKX 交易账户 300U
        ├─ ~72U/轮 ─(P1 maker 买)→ ETH
        │      ─(P2 你操作)→ 提币(以太坊主网)→ hot wallet → OSL 资金账户
        │      ─(你在 OSL 划转)→ OSL 交易账户 ─(P3 你卖出)→ USD
        └─ 其余留作 1x 空单保证金 ──(P1 开空 … P3 平空)──→ 平仓后剩余 USDT

每轮对账:本轮开始时交易账户 USDT − 本轮结束时交易账户 USDT = 消耗的 USDT
          对比  本轮 OSL 卖出所得 USD
```

## 3. 两个核心概念

### 3.1 目标空单 = 还没卖掉的 ETH

```
目标空单(ETH) = 本轮手里还持有、还没卖掉的 ETH
偏差          = OKX 实际空单 − 目标空单
```

- **P1**:每买到一点 ETH,目标空单变大 → 程序补开空单
- **P2**:目标空单不变(ETH 在路上,空单原样保留)
- **P3**:你每输入一笔卖出,目标空单变小 → 程序平掉对应空单

程序**不是**「收到一笔就处理一笔」,而是**每次都重新算一遍偏差,再把偏差补齐**。这样重复推送、漏消息、断线、重启都不会造成重复开平仓。P3 里你输错了数,改正以后程序也会按新的目标自动对齐(第 8.4 节)。

### 3.2 真正的成交价格是「兑换率」

对冲以后 ETH 涨跌基本抵消,整件事的本质是把 USDT 换成 USD:

```
每笔兑换率 ≈ OSL 卖出价 × (1 − OSL taker 费 0.05%) ÷ OKX 平空价
整轮兑换率 = OSL 收到的 USD ÷ 本轮消耗的 USDT
```

2026-10-14 实测:OSL ETHUSD 买一 2480.46,OKX ETH-USDT 卖一 2482.29,扣掉 OSL taker 费后兑换率约 0.9988。`market` 命令会实时显示这个数,帮你挑卖出时机。

## 4. 前置要求(Requirements)

### 4.1 OKX

| 项 | 要求 | 原因 |
|---|---|---|
| 账户 | **主账户**(已决定) | 前提:主账户里没有别的 ETH-USDT 永续仓位,也不手动交易它;程序每轮开始前检查这个仓位必须为 0 |
| 账户模式 | **合约模式**(API 里 `acctLv=2`,以前叫「单币种保证金」) | 现货模式开不了永续;合约模式下 USDT 永续只用 USDT 做保证金,ETH 现货不算保证金,提走 ETH 不影响空单。第一次切换要在网页/App 上手动操作 |
| 持仓模式 | **单向持仓**(`net_mode`)优先 | 只有单向持仓才能用 `reduceOnly`;双向持仓也能跑(平空单自动只减仓),程序启动时读取并自适应 |
| 杠杆 | ETH-USDT-SWAP 全仓 1x | 程序预检时检查,不对就设置 |
| API Key | **读取 + 交易**;不开提币 | 资金账户↔交易账户划转属于「交易」权限,不需要提币权限 |
| IP 白名单 | 你的 IP 不固定,**不绑** | 代价:没绑 IP、有交易权限的 key 连续 14 天不用会自动失效,到时重建;key 不开提币,泄露也提不走钱 |
| 提币地址 | hot wallet 地址提前加进白名单 | 新地址可能有冷却期,提前一天弄好 |
| 提币网络 | **以太坊主网**(ERC20) | OSL 只收以太坊主网的 ETH,不支持 L2 |
| 现货手续费币种(可选) | 可以设成用 USDT 扣手续费 | 默认买单手续费从买到的 ETH 里扣;改成 USDT 扣,买多少 ETH 就是多少,对冲更好算。不改程序也能处理 |

### 4.2 OSL

| 项 | 要求 | 原因 |
|---|---|---|
| API Key | **不需要** | 程序只读 OSL 公开行情,不用登录 |
| hot wallet | **必须先在 OSL 做钱包白名单验证**(App 里 WalletConnect 签名,或小额精确金额转账验证) | OSL 规定「未验证不入账」;交易所直接充值到 OSL 是禁止的,所以必须经过 hot wallet |

## 5. 命令行设计

所有命令前缀 `offramp`。`buy` 支持 `--dry-run`:用真实行情照常计算,只打印「本来会怎么下单」,不真正下单。

| 命令 | 阶段 | 做什么 |
|---|---|---|
| `check` | P0 | 预检(见 5.1) |
| `market` | 任意 | 实时显示 OKX 现货/永续、OSL ETHUSD 盘口,以及扣费后的兑换率;只读 |
| `round new [--usdt 300]` | P0 | 新建一轮;可选从 OKX 资金账户划转 USDT 到交易账户(划转后再查划转状态确认到账);记录本轮开始时交易账户 USDT |
| `buy --usdt 72` | P1 | maker 买 ETH + 同步开空,前台运行,实时输出(第 7 节) |
| `buy resume` | P1 | 中断后恢复 |
| `status` | 任意 | OKX 交易账户 USDT/ETH、空单、保证金率、强平价、累计资金费;本轮状态、偏差、在途时长 |
| `okx to-funding` | P2 | (可选)把本轮 ETH 从交易账户转到资金账户。OKX 只能从资金账户提币;也可以在 App 里自己转 |
| `sell` | P3 | 卖出助手,交互式,前台运行(第 8 节) |
| `round close` | P4 | 收尾:平掉剩余空单尾数、记录本轮结束时交易账户 USDT |
| `report [--round N \| --all] [--osl-usd X] [--gas-eth X]` | P4 | 输出 PnL 对账(第 10 节) |

### 5.1 `check` 预检内容

- OKX API 能连通、签名正确、权限正确;**有提币权限就警告**
- 本机时间和 OKX 时间差 < 1 秒
- 账户模式、持仓模式、ETH-USDT-SWAP 杠杆和保证金模式;有没有维护公告
- 读取并缓存规格:OKX 现货/永续的最小下单量、数量步长、价格步长、每张合约 ETH 数;OSL ETHUSD 公开行情能否读到
- 读取 OKX 费率
- OKX ETH 主网提币是否正常、提币手续费多少(只提示)
- 本地数据库里有没有未完成的轮次

## 6. 每一轮的操作步骤

| 步骤 | 谁 | 操作 | 完成标准 |
|---|---|---|---|
| 1 | 你 | `offramp check` | 全部通过 |
| 2 | 你 | `offramp market` 看一会儿 | 了解当前兑换率区间 |
| 3 | 你 | `offramp round new --usdt 300`(第二轮不用再划转,`round new` 即可) | 交易账户 USDT 到账 |
| 4 | 你 | `offramp buy --usdt 72`(第一次先 `--dry-run`) | 买完;程序显示空单 = 持有 ETH |
| 5 | 你 | `offramp okx to-funding` | ETH 在可提币的资金账户 |
| 6 | 你 | OKX 提币到 hot wallet(**以太坊主网**);hot wallet 再转到 OSL 充值地址 | 两笔交易都已上链 |
| 7 | 你 | OSL 到账后(一般 5–15 分钟),在 OSL 把 ETH 从资金账户划到交易账户 | **本轮 ETH 全部在 OSL 交易账户、可用** |
| 8 | 你 | `offramp sell`,先按提示输入 OSL 上看到的到账数量 | 程序平掉多出来的空单,显示空单 = 到账 ETH |
| 9 | 你 + 程序 | `offramp sell`:你在 OSL 卖,每卖一笔在程序里输入成交量 | 卖完;空单归零(或只剩尾数) |
| 10 | 你 | `offramp round close` | 无空单 |
| 11 | 你 | `offramp report --osl-usd <OSL 实际收到的 USD>` | 「未解释差额」≈ 0 |
| 12 | 你 | 在 OSL 把 USD 划回资金账户,手动出金(USD 最低 50) | — |

**第 8 步的细节:**
- 到账的 ETH 会比买到的少(OKX 提币费 + hot wallet 的 gas),所以空单会略多于到账 ETH,程序会把多出来的部分平掉(不足半个最小单位就不动)。
- 如果你输入的数量**比空单还多**,程序会提示并要求你确认(可能是账户里本来就有别的 ETH)。
- 必须**全部到账后**才填到账数量。如果一部分还在路上就申报,程序会把在途 ETH 的对冲平掉。

## 7. P1 引擎:OKX maker 买 + 同步开空(全自动)

这是现在唯一全自动的部分,也是程序里最需要严谨的地方。原来为 OSL maker 卖设计的引擎原样用在这里,只是方向反过来(以后能用 OSL API 时,同一套引擎直接用在卖出上,见附录 B)。

### 7.1 两条腿

| | 内容 |
|---|---|
| maker 腿 | OKX `ETH-USDT` 现货,`post_only` 限价买 |
| 对冲腿 | OKX `ETH-USDT-SWAP` 卖出开空,IOC 限价(taker) |
| 持有 ETH | 累计买入成交 − ETH 手续费 |
| 目标空单 | = 持有 ETH |

### 7.2 主循环

所有下单、撤单决策都在**一个循环**里串行完成(v1 每秒用 REST 查一次订单、行情和仓位),决策之间不会互相抢,避免并发竞态。

```
每当有事件(成交回报 / 行情 / 仓位更新),或每 1 秒:
  1. 健康检查
       行情超过 stale_ms 没更新,或私有推送断开
         → 撤 maker 单,本次不挂新单
  2. 对冲器 step()            ← 永远先对冲
  3. 风控检查
       未对冲 ETH 超限 / 对冲连续失败 / 保证金不够
         → 撤 maker 单,进入 PAUSED
  4. 报价器 step()            ← 只有 RUNNING 状态才挂单
  5. 完成判断:预算花完(剩余不够最小下单量)且偏差为 0
```

另外每 5 秒用 REST 补查一次订单、成交和仓位,防止推送漏消息。

### 7.3 对冲器

```
对冲器 step():
    如果有对冲单还在途:           跳过   (同一时间只允许一笔)
    如果上一笔成交后仓位还没刷新:  跳过   (仓位确认锁)

    目标张数 = 取整到最小单位(持有ETH ÷ 0.1)
    实际张数 = OKX 当前空单张数
    偏差     = 实际张数 − 目标张数

    偏差 ≤ −最小下单量 → 卖出开空  IOC  数量=−偏差  限价=永续买一×(1−滑点上限)
    偏差 > 半个单位   → 异常(空单比 ETH 多)→ HALTED
```

要点:

1. **仓位确认锁**:IOC 成交后,仓位推送可能晚几百毫秒才到。如果这时就用旧仓位算偏差,会**再开一次**。所以一笔对冲成交后,要等仓位更新(或 REST 查到预期仓位)才允许下一次计算。
2. **对冲用 taker**:对冲要快,不追求 maker。
3. **IOC 没成交**:下一轮用最新价格重试;连续 N 次失败 → PAUSED,撤掉 maker 单。IOC 限价要先夹在 OKX 限价范围内(`/public/price-limit`),否则会被拒。
4. **客户端订单号**:OKX 只允许字母和数字、最长 32 位,格式如 `r1h0007`(第 1 轮第 7 笔对冲)、`r1m0003`(第 1 轮第 3 笔 maker)。重复订单号会被拒(错误码 51016)。下单超时就按这个号查,查清之前不下新单。
5. **不足一个最小单位的偏差**:先累积,够一个单位再下单。OKX ETH 永续每张 0.1 ETH,最小 0.01 张,也就是**最小单位 0.001 ETH**(约 2.5 USDT),最大残留误差 0.0005 ETH。
6. **数量换算**:合约规格每次启动时从接口读,不写死。

### 7.4 报价器(现货 maker 买)

```
价格上限 = 永续买一 × (1 + max_entry_basis)        ← 现货买价不能比能开空的价格贵太多
挂单价   = min(现货买一(扣掉自己的单)[或 +1 步长], 价格上限, 现货卖一 − 1 步长) → 向下取整到 0.01
挂单量   = min(剩余预算 ÷ 挂单价, max_slice)       → 向下取整到 0.000001;< 0.0001 ETH 就结束
```

**什么时候撤单重挂**(一律撤单再挂新单):

| 条件 | 动作 | 节流 |
|---|---|---|
| 挂单价已高于价格上限(永续跌了,现货买贵了) | **立刻撤** | 不节流 |
| 挂单价比当前应挂价格低超过 `requote_bps`(被别人抬价,排不到) | 撤单跟价,但不高于上限 | 两次重挂至少间隔 `requote_min_interval` |
| 挂单价比当前应挂价格高(盘口下移) | 撤单往下重挂 | 同上 |
| 挂单存在超过 `max_order_age` | 撤单刷新 | — |
| 行情过期、风控暂停 | 撤单,不重挂 | — |

**要点:**

1. **算盘口时扣掉自己的单**:不然程序会以为买一是别人的价格,然后自己抬自己,无限往上挂。
2. **为什么要跟着永续撤单**:ETH 急跌时,现货买单会在旧价格被砸到,而你随后要在更低的价格开空,每次都亏这段差价。所以永续一跌就要先撤再挂。
3. **POST_ONLY 会吃单时**:OKX 直接拒单,按「结束、成交 0」处理,下一轮按最新盘口重挂;连续 N 次被拒,暂停一段时间。
4. **同一时间只挂一个买单**:用 `max_slice` 控制每单大小。测试时故意设小,让一轮里出现多次部分成交。
5. **对冲还没跟上时不挂新单**。
6. **挂着的买单会冻结 USDT**:合约模式下,被冻结的 USDT 不能再当保证金用。冻结太多,开空时保证金就不够,对冲会失败。所以每次挂单前都检查:
   ```
   挂单后剩余可用 USDT ≥ (已持有 ETH + 本单 ETH) × 价格 ÷ 杠杆 × (1 + margin_buffer)
   ```
   不满足就缩小挂单量。
7. **手续费从 ETH 里扣**:成交回报里 `fillFeeCcy=ETH`(负数表示收费),持有 ETH 按扣费后的数量算。改成 USDT 扣手续费后这一步就不需要了。

### 7.5 订单状态与竞态

**maker 单的状态:**

```
空闲 → 下单中 → 挂单中(可能部分成交) → 撤单中 → 结束(全部成交 / 已撤 / 被拒)
          ↘ 状态未知(超时)→ 按客户端订单号查 → 挂单中 / 结束 / 查不到则锁住并提示
```

**四条硬规则:**

1. **同一时间最多一个未结束的 maker 单**。上一单「结束」后才能挂新单。
2. **撤单不等于撤单成功**。撤单中依然可能成交,必须等交易所返回最终状态,读取最终累计成交量,再算剩余预算。
3. **已成交量以「订单累计成交量」(`accFillSz`)为准,只增不减**(每次收到回报取较大值),重复或乱序的回报不会让数字算两次。逐笔成交(`tradeId` 唯一)用来算均价和手续费,并和累计成交量交叉核对。
4. **每次下单前校验**:已花 + 挂单占用 ≤ 本轮预算。永远不会多买。

| 竞态 | 处理方式 |
|---|---|
| 撤单请求发出后又成交 | 等最终状态,按累计成交量算 |
| 成交回报和订单状态先后乱序 | 累计成交量取较大值,和到达顺序无关 |
| 同一笔成交推送两次 | 同上;逐笔成交按 `tradeId` 去重 |
| 某次查询失败或超时 | 跳过这一轮,下一轮重新查;行情超过 5 秒拿不到就撤单 |
| 下单超时,不知道成没成功 | 按客户端订单号查,查清之前不下新单 |
| 开空已成交,仓位推送还没到 | 仓位确认锁 |

### 7.6 运行状态与风控

| 状态 | 含义 | maker 单 | 对冲器 |
|---|---|---|---|
| RUNNING | 正常 | 挂 | 运行 |
| PAUSED | 暂停买入 | 撤掉 | **继续运行**,保持空单 = 持有 ETH |
| HALTED | 出现程序不能自己处理的偏差 | 撤掉 | 停止,等你处理 |

**进入 PAUSED**(条件恢复后自动回到 RUNNING):行情过期、私有推送断开;对冲连续失败 N 次;未对冲 ETH 超过 `max_unhedged_eth` 持续 `max_unhedged_s` 秒;保证金率低于阈值;POST_ONLY 连续被拒 N 次。

**进入 HALTED**(需要你确认后用 `resume` 恢复):空单和持有 ETH 对不上且不是程序造成的(ADL 或有人手动操作);启动或恢复时偏差超出容差;有订单状态一直查不清;本机时间偏差过大。

**Ctrl+C**:撤 maker 单 → 等最终状态 → 对冲器最后对齐一次 → 保存 → 退出。空单保留,程序绝不会一键平掉所有空单。

### 7.7 重启恢复(`buy resume`)

1. 读本地数据库:本轮预算、所有订单
2. 去 OKX 查:本轮所有订单的最终状态和累计成交,以及当前仓位
3. 撤掉本程序遗留的 maker 单(用客户端订单号前缀识别),等最终状态
4. 重新计算持有 ETH 和偏差:在容差内 → 对冲器对齐后继续;超出 → HALTED,打印明细
5. **单实例锁**:同一时间只能有一个进程在跑

## 8. P3 卖出助手:你在 OSL 卖,程序同步平空

### 8.1 为什么推荐吃单(taker)卖,而不是手动挂 maker

| | 吃单卖(推荐) | 手动挂 maker |
|---|---|---|
| 手续费 | 0.05% | 0% |
| 风险窗口 | 你在 OSL 点卖出 → 在程序里按回车,几秒钟 | 挂单 → 被吃 → 你发现 → 输入,可能几十秒到几分钟 |
| 风险方向 | 涨跌对称 | 对你不利:maker 卖单通常是 ETH 上涨时被吃,你随后要在更高的价格平空 |

OSL ETHUSD 价差只有约 0.1 bps,吃单的代价基本就是 0.05% 手续费。手动挂 maker 省下这 0.05%,但要承担上面那个不利的风险窗口,v1 不推荐。如果以后想试,见 8.5。

粗算一下(按 ETH 年化波动 60%):ETH 价格的标准波动在 10 秒内约 3.4 bps,30 秒约 6 bps,1 分钟约 8 bps。maker 单又偏偏在价格往不利方向走的时候成交,所以只要从成交到平空的反应时间超过半分钟左右,不利波动就可能吃掉省下的 5 bps。吃单则完全由你掌握节奏:先卖,马上回车,OSL 成交多快都没关系。

### 8.2 交互流程

**分工:OKX 平空是全自动的(下单、重试、确认仓位都由程序做),你只需要在 OSL 卖完后按一下回车,告诉程序「卖了」。** 程序看不到你的 OSL 账户(零售没有 API),所以这一下回车是唯一需要你给的信号。

```
$ offramp sell
本轮到账 0.0287 ETH(已申报),OKX 空单 0.029 ETH ✓

 OSL ETHUSD   买一 2480.46   卖一 2480.49
 OKX 永续     卖一 2482.30
 吃买一卖出的净兑换率  0.99876(已扣 OSL taker 0.05%)
 剩余待卖  0.0287 ETH  ≈ 71.2 USD

 ▶ 本笔:在 OSL 市价卖出 0.0287 ETH,卖完直接按回车
   (卖的数量不一样就输入实际数量,可加 @均价)
 > ⏎

[14:02:11] 记录卖出 0.0287 ETH
[14:02:11] OKX 平空  买 0.029 ETH IOC 只减仓 → 成交 @ 2482.35
[14:02:11] 对齐      空单 0 = 剩余 0 ✓
 本轮卖完。用 offramp round close 收尾。
```

**操作要点:**
- **先让程序停在输入提示上,再去 OSL 点卖出**,卖完马上切回来按回车。风险窗口只有几秒钟。
- **按回车 = 按屏幕上显示的「本笔」数量平空**。最省事的做法是在 OSL 用市价单把显示的数量一次卖完,回来直接回车,不用打字。
- 数量小时「本笔」就是全部剩余。数量大时(超过 `chunk_eth`,默认 2 ETH)程序会建议分几笔卖,减少 OSL 的滑点;每卖一笔按一次回车。
- 如果实际卖的数量和显示的不一样(比如限价单只成交了一部分),就输入实际数量。
- 均价可以不填。填了的话,报告可以按笔算兑换率;不填的话只算整轮兑换率。

### 8.2.1 可选:先平空,再卖

把顺序反过来:你按回车 → 程序先在 OKX 平掉「本笔」数量 → 屏幕提示「已平空 0.029,现在去 OSL 卖 0.0287」→ 你去 OSL 卖。

| | 先卖后平(默认) | 先平后卖 |
|---|---|---|
| 风险窗口 | 几秒钟,这期间是净空头(怕涨) | 几秒钟,这期间是净多头(怕跌) |
| 风险大小 | 一样 | 一样 |
| 万一出问题 | OSL 卖了但 OKX 平不掉:程序会一直重试 | OKX 平了但 OSL 卖不出去(App 卡、维护):你手里有没对冲的 ETH,要么尽快卖,要么用 `fix` 重新开空 |

默认用「先卖后平」:OSL 吃单几乎一定能成交,不确定的是 OKX 那一腿,而 OKX 这一腿程序可以自动重试。用 `offramp sell --close-first` 切换顺序。

### 8.2.2 为什么不能完全不按回车

要让程序自己发现「你在 OSL 卖了」,只有三种办法:
1. **OSL API 的私有成交回报**:零售用不了(见附录 B)。
2. **看 OSL 公开逐笔成交来猜**:别人的卖单也会出现在公开成交里,程序分不清是不是你的,猜错就会提前平空。不可靠,v1 不做。
3. **用浏览器自动化操作 OSL 网页**(程序替你登录、下单、读成交):技术上能做,但很可能违反 OSL 用户协议,出金账户被冻结的代价太大,而且要把登录密码和二次验证交给程序。**不建议。**

所以一次回车是零售账户下最稳的做法。

### 8.3 程序在每次输入后做什么

```
已卖(申报) += 输入数量
剩余 = 到账 ETH − 已卖(申报)
目标空单 = 剩余   → 交给 7.3 的同一个对冲器对齐(方向是买入平空,IOC + reduceOnly)
```

**输入检查:**
- 直接回车 → 按屏幕上显示的「本笔」数量处理,不需要二次确认
- 手动输入的数量 > 剩余待卖 → 拒绝,提示重新输入
- 手动输入的数量和「本笔」差很多(超过剩余的 50% 且超过 0.1 ETH)→ 要求再按一次回车确认(防止多打一个 0)
- 格式不对 → 拒绝,不做任何操作

**平空的安全规则**(和 P1 对冲器一样):
- 只减仓(单向持仓用 `reduceOnly=true`,双向持仓用 `posSide=short`),永远不会平过头变成多单
- 平仓数量先和实际空单取较小值,否则 OKX 会整单拒绝
- IOC 没成交 → 立刻用最新价格重试;连续 3 次失败 → 红字提示,让你决定继续重试还是手动处理
- 仓位确认锁、客户端订单号、超时先查单,规则同 7.3

### 8.4 输错了怎么办

因为程序是按「目标空单 = 剩余 ETH」对齐的,改正申报数量就行:

```
 > fix 0.0200        ← 把「已卖」改成 0.0200(比如你刚才多输了)
[14:03:05] 已卖改为 0.0200,剩余 0.0087,目标空单 0.009,实际空单 0
[14:03:05] 需要重新开空 0.009 ETH,确认? (y/n) > y
[14:03:06] OKX 开空 0.009 ETH → 成交 ✓
```

- `fix` 是唯一可能让程序在 P3 里**开空**的操作,所以一定要你确认
- `undo` = 撤销上一次输入(等价于 `fix` 到上一次的值)

### 8.5 (可选,v1.1)手动挂 maker 的成交提醒

如果以后想手动挂 maker 省 0.05%:
- 你在 OSL 挂好卖单后,告诉程序价格和数量:`watch 2480.60 0.0287`
- 程序订阅 OSL 公开逐笔成交(不需要登录):
  - 出现**高于**你挂单价的成交 → 按价格优先规则,你的单**一定已全部成交** → 响铃 + 红字提示
  - 出现**等于**你挂单价的成交 → 你的单**可能部分成交** → 响铃提示去 App 确认
- 程序**只提醒,不自动平仓**。因为它看不到你的单是不是还在(你可能已经撤了或改了),自动平仓可能把对冲平掉。确认后你照常输入成交量。

## 10. PnL 对账(`report`)

**数据来源:**
- OKX(自动):本轮开始、结束时交易账户 USDT;所有成交和手续费;账单里的资金费
- OSL(你提供):
  - `--osl-usd`:OSL 交易账户里本轮实际收到的 USD(App 里看)
  - P3 里输入的每笔数量和均价,用来交叉核对:Σ 数量 × 均价 × (1 − 0.05%) 应该 ≈ `--osl-usd`
  - 以后可以加 `--osl-csv`,直接导入 OSL 网页导出的成交记录【待核实 OSL 是否支持导出】
- 转账损耗:P1 买到的 ETH(扣费后)− `sell` 开始时填的到账 ETH
- `--gas-eth`(可选):如果 hot wallet 用别的 ETH 付 gas,程序看不到,需要你填

**报告示例:**

```
====== 第 1 轮对账 ======
本轮开始时交易账户 USDT              300.00
本轮结束时交易账户 USDT              227.93
→ 消耗 USDT                           72.07

成本分解(按 1 USD ≈ 1 USDT 近似,只用来看钱花在哪)
  现货买入手续费                      0.xx
  买入价 vs 开空价(入场基差)          ±0.xx
  永续开仓 / 平仓手续费               0.xx
  资金费(收为正,付为负)              ±0.xx
  转账损耗(提币费 + gas)              0.xx   ← 小额时这一项占比最大
  OSL taker 手续费 0.05%              0.04
  OSL 卖价 vs OKX 平仓价              ±0.xx
  对冲时间差 / 尾数                   ±0.xx
  未解释差额(应 ≈ 0)                 0.00

核对:P3 输入合计 71.15 USD  vs  你输入的 71.15 USD  ✓

```

「未解释差额」不为 0,说明有费用或成交没被记到,需要查。`report --all` 把所有轮次加总。

## 12. 异常场景清单

| 阶段 | 场景 | 不处理会怎样 | 处理方式 |
|---|---|---|---|
| P1 | POST_ONLY 会吃单被拒 | 死循环重挂 | 按最新盘口重挂,连续 N 次暂停 |
| P1 | 盘口里有自己的单 | 自己抬自己的价 | 计算盘口时扣掉自己的挂单 |
| P1 | 撤单过程中成交 | 多买 | 等最终状态,按累计成交量算剩余预算 |
| P1 | 现货买单冻结 USDT 导致保证金不够 | 开不了空,裸多 | 挂单前做保证金检查 |
| P1 | 现货手续费从 ETH 里扣 | 空单比实际 ETH 多 | 按扣费后的 ETH 算目标空单 |
| P1 | 急跌时 maker 买单被砸 | 高价买、低价开空 | 报价跟着永续,一跌先撤 |
| P1/P3 | 对冲量不足最小下单量 | 被拒 | 累积到一个单位再下 |
| P1/P3 | 平仓量大于实际空单 | 整单被拒 | 下单量和实际空单取较小值 |
| P1/P3 | IOC 价格超出限价范围 | 下不了单 | 先读限价范围,把价格夹在里面 |
| P1/P3 | 下单超时 | 重复下单 | 按客户端订单号查,查清前锁住 |
| P1/P3 | 对冲成交后仓位推送晚到 | 重复开/平 | 仓位确认锁 |
| P2 | 到账 ETH 少于买入(提币费、gas) | 空单多出来 | `sell` 开始填到账数量时平掉多出的部分 |
| P2 | 提币选错网络(不是以太坊主网) | ETH 到不了 OSL | 预检和步骤里明确提示 |
| P2 | hot wallet 没做白名单验证 | OSL 不入账 | 开工前完成验证 |
| P2 | 一部分 ETH 还在路上就填到账数量 | 在途 ETH 失去对冲 | 步骤里明确要求全部到账;输入数量明显少于空单时程序要求确认 |
| P2 | 在途时间很长 | 资金费照算 | `status` 显示在途时长和累计资金费 |
| P3 | 卖出后忘了输入 | 空单比剩余 ETH 多,ETH 跌没事,涨了亏 | 程序在输入提示上每 30 秒提醒一次「剩余待卖 X」;卖完前不要关程序 |
| P3 | 输入数量多打/少打 | 平多了或平少了 | 输入检查 + 大额二次确认 + `fix` / `undo` |
| P3 | OKX 断线,平不了空 | 风险窗口变长 | 红字提示,先别继续卖;重连后自动对齐 |
| 系统 | 同时跑了两个进程 | 开平两次 | 单实例锁 |
| 系统 | 本机时间不准 | 签名失败 | 预检和运行中检查时间差 |
| 系统 | 程序崩溃或重启 | 状态丢失 | 数据库 + 恢复流程 |
| 系统 | OKX key 没绑 IP 闲置 14 天 | key 失效 | 重建 key;`check` 会报连接失败 |
| 仓位 | 保证金率下降 | 被强平 | 低于阈值暂停 + 提示补保证金 |
| 仓位 | ADL 或手动操作改了仓位 | ETH 和空单对不上 | 发现不是程序造成的变化 → HALTED |

## 13. 测试计划

### 13.1 第一层:本地模拟(不花钱)

用一个**假 OKX**(和真实接口同一套)按剧本制造以下情况,逐个验证:
- P1:部分成交、一次全部成交、多次小额成交(不足一个最小单位);成交推送重复、和状态乱序;撤单过程中成交;下单超时(实际成功 / 实际失败);POST_ONLY 连续被拒;IOC 不成交;仓位推送延迟;行情中断;对冲中途崩溃后恢复
- P3:正常输入、拆多笔输入、多打一个 0、`fix` / `undo`、平仓 IOC 连续失败

每个剧本跑完都检查四条规则:
1. 永远不会出现多单
2. 累计买入不超过预算;累计平仓不超过申报卖出
3. 稳定后 |空单 − 持有 ETH| ≤ 0.0005 ETH
4. 同一笔成交只记一次

### 13.2 第二层:`buy --dry-run` + `market`(不花钱)

接真实行情,报价器照常计算,只打印、不下单。看挂单价在盘口什么位置、多久会触发重挂;同时用 `market` 看 OSL 兑换率的正常区间。

### 13.3 第三层:OKX 模拟盘

**P1 可以完整测**:两条腿都在 OKX。模拟盘 key 要在模拟盘里单独创建,请求加 `x-simulated-trading: 1`。P3 的平空逻辑也能在模拟盘上测(在助手里输入假的卖出量)。

### 13.4 第四层:小额实盘

两边最小下单量都很小:OKX 永续最小 0.001 ETH(约 2.5U),OSL 最小 0.00052 ETH 或 1 USD。**300U 足够**:

| 用途 | 金额 |
|---|---|
| 第一轮买 ETH | ~72U(约 0.029 ETH,`max_slice=0.010` 会拆成 3 单以上) |
| 第二轮买 ETH | ~72U |
| OKX 空单保证金(两轮共用) | ~150U |
| 合计 | 300U |

注意:
- 两轮都卖完后合计约 140 USD,**再一起出金**(USD 出金最低 50)
- 第一轮先 `buy --dry-run` 看一遍,再真跑
- 金额小时,OKX 提币费、主网 gas 这些固定成本占比很高,测出来的兑换率不代表正式规模

## 附录 B:以后能用 OSL API 时(成为 PI 或开通企业账户)

P3 可以直接改成全自动 maker 卖,用的就是第 7 节同一套引擎,把 maker 腿换成 OSL:

- **maker 腿**:OSL `POST /api/v5/order`,`type=LIMIT`、`timeInForce=POST_ONLY`、`newClientOrderId`;撤单 `DELETE /api/v5/order`;OSL 没有改单接口,一律撤单再挂
- **成交来源**:私有 WebSocket `orders` 频道的累计成交量 `accBaseVolume` 只增不减;`GET /api/v5/trades` 按订单补查。OSL 的推送没有序号、不能重放,断线后必须先 REST 补查
- **报价锚定 OKX**:
  ```
  底价   = OKX 永续卖一 × r_min × (1 + OKX taker 费 + 对冲滑点)
  挂单价 = max(OSL 卖一(扣掉自己的单)[或 −1 步长], 底价, OSL 买一 + 1 步长)
  ```
  OKX 一涨就先撤单,防止 ETH 急涨时卖单在旧价格被吃、随后高价平空
- **对冲腿**:第 7.3 节的对冲器,方向改成买入平空(IOC + reduceOnly)
- **OSL 特有的坑**:POST_ONLY 会吃单时订单被拒,原因是 `CANCEL_BECAUSE_POST_ONLY_WILL_FILL`;系统维护会撤掉所有挂单;限流每分钟 1800 次,超了会被封 60 秒;REST key 不能绑 IP,所以 key 绝不能开资金权限
- **签名**:REST 用请求头 `api-key`、`api-expires`、`api-signature`,签名算法是 HMAC-SHA512;WebSocket 登录用 HMAC-SHA256
